# Stele

> **στήλη** — 古希腊立于路旁的石碑。法令、条约、罪状刻于其上，公开供所有人查验。
> 石头不会被删除，不会被修改，不会被遗忘。

一个把"该被追责的"和"该被记住的"刻下来的仓库。

---

## 两个板块

| 目录 | 名称 | 装什么 |
|---|---|---|
| [`01-Exhibits/`](01-Exhibits/) | **呈堂证物** | 违法网站的取证记录与可直接提交的举报材料 |
| [`02-Annals/`](02-Annals/) | **史册** | 在主流平台易被删除的公共事件史料 |

**Exhibits** 取自法庭惯例——证据按 Exhibit A、B、C 编号呈堂。这里每个钓鱼站、每个诈骗站就是一件物证，编号入库，附截图、页面源码、哈希与填好的举报词。

**Annals** 取自拉丁语 *annus*（年），是古罗马逐年记载国家大事的官方册子。"赛博史官"的本义就在这里：不是评论，是登记。

## 从这里开始

### 我想举报一个诈骗网站

1. 打开 [`01-Exhibits/`](01-Exhibits/)，对照索引找到同类型的案例
2. 复制该条的 `report/12377.md` 全文
3. 前往 [12377 违法和不良信息举报中心](https://www.12377.cn/jbxzxq/zpljbxzxq.html)（诈骗类入口）
4. 粘贴举报词，上传对应截图

整个过程约三分钟，不需要懂技术。

### 我想查某个事件的来龙去脉

打开 [`02-Annals/`](02-Annals/)，每个事件按四层分开存放：

```
01-facts     官方认定 —— 法院判决、校方通报、政府文件
02-reports   正规媒体报道 —— 有署名、有日期、有可回溯链接
03-claims    争议与观点 —— 当事人陈述、博主评论（明确标注为观点）
04-debunked  已辟谣 —— 官方点名否定的说法，"传言 → 核查结论"
```

四层不许混放。**看到"据说""网传"时，先去 04-debunked 查一遍。**

## 三条规矩

**一、域名一律混淆。**
全仓库不出现任何可点击的违法站点链接，统一写作 `example[.]com` 形式。原因很实际：GitHub 权重高，活链会被搜索引擎索引，等于替诈骗站做推广。

**二、没有来源的断言不入库。**
每条记录必须挂：来源名称、原文 URL、发布日期、采集时间、Wayback 存档链接。查不到一手材料的位置显式标 `status: pending-source`，留白而不猜测。

**三、不重新分发被删内容本体。**
被封禁的视频、文章只记录元数据（标题、作者、发布时间、下架时间、镜像指向），不搬运内容。这是版权边界，也是这个仓库能长期存在的前提。
