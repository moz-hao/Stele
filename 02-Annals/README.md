# Annals — 史册

> 拉丁语 *annus*（年）。古罗马祭司逐年登记大事，刻于白板，立于广场。
> 这里做的不是评论，是登记。

---

## 编辑原则（不可协商）

### 一、四层分离

每条信息必须落进且只落进一个抽屉：

| 目录 | 内容 | 准入标准 |
|---|---|---|
| `01-facts` | 官方认定 | 有发布主体、有文号或可追溯的正式发布 |
| `02-reports` | 正规媒体报道 | 有署名媒体、发布日期、可回溯链接 |
| `03-claims` | 争议与观点 | 当事人陈述、自媒体评论——**开头必须标注"以下为观点"** |
| `04-debunked` | 已被官方否定 | 附辟谣主体与原文依据 |

**四层不许混放。** 把 `03-claims` 当事实引用，是这份档案最容易被误用的地方。

### 二、每条记录强制字段

```
来源名称 / 原文 URL / 发布日期 / 采集时间 / Wayback 存档链接 / 原文摘录
```

摘录**不做改写**。需要概括的地方另起一行写「概括：」。

### 三、缺口处理

查不到一手材料的位置，写：

```yaml
status: pending-source
channels_checked: [已检索的渠道列表]
```

**留白，不猜测。** 二手转述不得冒充一手材料。

### 四、被删内容

被封禁的视频、文章只记录元数据：

```
标题 / 作者 / 平台 / 标识符（BV号等）/ 发布时间 / 下架时间 / 状态码 / 镜像指向
```

**不搬运内容本体。** 这是版权边界，也是本仓库能长期存在的前提。

## 为什么值得存

平台会删帖，账号会注销，链接会 404。但公共事件的公共记录不该随之蒸发——

**不是为了记住谁对谁错**（那是法院的职责），而是为了在几年后有人问"当时到底发生了什么"时，还拿得出一份带出处的答案。
